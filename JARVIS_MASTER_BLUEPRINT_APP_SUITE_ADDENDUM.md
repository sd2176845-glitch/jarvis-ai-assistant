# JARVIS Master Blueprint — App Suite Addendum

Date: 2026-11-22

This addendum belongs to the JARVIS Master Blueprint for the JARVIS Android assistant. It is separate from Even. These are approved planning entries only; none is claimed to be implemented, built, tested or verified by this document.

## Priority 39 — Dedicated App Suite

Create the following optional, modular app experiences under the JARVIS ecosystem. Reuse existing authentication, permissions, memory, knowledge, workflow, scheduling, diagnostics, security and connectivity foundations. Do not create duplicate schedulers, memory stores, account systems or automation engines.

1. **AI Learning Academy** — owner-selected learning paths for coding, science, technology and other subjects, with lessons, practice, progress tracking and source-aware explanations. Reuse the planned Personal Education & Skill Academy in Priority 38; this app is its dedicated user interface, not a second learning engine.
2. **Personal Productivity Studio** — a workspace for tasks, projects, goals and planning. Reuse existing structured tasks, calendar/reminder and workflow foundations; do not create a parallel task database or scheduler.
3. **Creative Media Studio** — a guided workspace for creating and organizing images, videos, presentations and other creative drafts through supported tools. Clearly label generated/draft assets and obtain approval before publishing or sharing.
4. **Data Intelligence Center** — a workspace for analyzing owner-selected, authorized datasets and producing charts, summaries and reports. Preview imported data, minimize sensitive fields, explain assumptions and avoid uploading private data without explicit consent.
5. **Smart Home Studio** — a dashboard for explicitly paired, compatible smart-home devices and routines. Show connection and device status, use authenticated integrations, require confirmation for consequential physical actions, and provide manual stop/off controls. Reuse the existing smart-home and workflow foundations.
6. **Software Development Studio** — a project workspace for repository-aware planning, code assistance, builds, tests and documentation. Reuse Priorities 13, 18 and 19; require explicit project selection and approval before file edits, commits or deployments. Preserve the strict separation between JARVIS and Even.

## Shared acceptance criteria
- Each app must display whether its functions are planned, available, permission-required, failed or verified.
- Use the existing owner authentication, privacy, permission and audit foundations.
- Keep each app modular; a failure in one app must not break core voice commands, notes or offline functions.
- Ask before external sharing, publishing, purchases, sending communications, device actuation, repository writes or deployment.
- Do not mark any app complete until implemented, built, tested and verified on the target Poco M4 Pro 4G where applicable.

All six app entries are planned only. Keep JARVIS separate from Even; do not modify Even.
